# Спецификация: анализатор занятого места на дисках

Документ из двух частей:

1. **Поведение оригинала** — что делает Scanner 2.13 (Steffen Gerlach, 2012, `scn2/`). Собрано по документации из комплекта, ресурсам формы и импортам WinAPI. Код оригинала не копируется: новая версия пишется с нуля по этому описанию.
2. **Новая версия** — что сохраняем, что улучшаем и на чём пишем.

## Часть 1. Поведение оригинального Scanner

### 1.1. Назначение

Показывает, чем занято место на дисках. Все файлы и папки выбранного диска (или нескольких дисков) рисуются на одной диаграмме. Площадь каждого сегмента пропорциональна месту, которое он занимает. Слишком мелкие объекты не рисуются: это инструмент для обзора, а не файловый менеджер.

### 1.2. Диаграмма

- Это расширенная круговая диаграмма из концентрических колец (sunburst). В центре текущий корень: диск, сводка или папка. Каждое следующее кольцо — следующий уровень вложенности.
- Угол сегмента пропорционален занятому месту относительно родителя.
- Сегменты, слишком маленькие для отрисовки, не рисуются, и в них нельзя приблизиться (известное ограничение).
- Края сглаживаются. Ради скорости отрисовки размер окна меняется рывками, кнопками «+» и «−», а не мышью.
- Свободное место на диске показывается отдельным сегментом («Free on X:»), занятое — «Used on X:».
- Отдельными сегментами выделяются корзина (Recycle Bin) и, в старых версиях, файл подкачки (Virtual Memory).

### 1.3. Взаимодействие с диаграммой

| Действие | Результат |
|---|---|
| Навести курсор на сегмент | В строке состояния сверху: путь, размер (автоматически байты/КБ/МБ/ГБ/ТБ), число файлов |
| Левый клик по папке | Приблизиться к ней (Zoom): папка становится центром диаграммы |
| Правый клик по сегменту | Контекстное меню (см. ниже) |

Контекстное меню сегмента (пункты зависят от типа объекта):

- **Show / Hide** — показать или скрыть содержимое папки на диаграмме;
- **Zoom** — приблизиться к папке;
- **Rescan** — пересканировать папку;
- **Open** — открыть файл или папку программой по умолчанию (`ShellExecute`);
- **Recycle** — удалить в корзину;
- **Remove** — удалить безвозвратно.

### 1.4. Панель управления

- **Кнопки дисков** (слева, по одной на каждый диск, найденный при запуске). Клик выбирает диск, повторный клик по выбранному запускает пересканирование. Тип диска (жёсткий, съёмный, сетевой, CD) показан иконкой.
- **Summary** — общая диаграмма по всем дискам, отмеченным для сводки.
- **Контекстное меню кнопки диска:**
  - «Summary» — включить диск в сводку или исключить из неё;
  - «Physical Device ID» 0–7 — номер физического диска. Разделы с разными номерами сканируются параллельно, разделы с одинаковым номером — по очереди.
- **Back** — вернуться к предыдущему корню (история переходов).
- **Parent Folder** — подняться на уровень выше.
- **Rescan Folder** — пересканировать текущую папку.
- **Software Removal** — открыть системное окно установки и удаления программ. После удаления программы диаграмму нужно обновить вручную.
- **Empty Recycle Bin** — очистить корзину. Изменение подхватывается автоматически.
- **«+» / «−»** — изменить размер окна ступенями.
- Ссылка «On the web / Donate» и номер версии внизу справа.
- **Клавиша `L`** — записать журнал `Scanner.log` (для отчётов об ошибках).

Число кнопок дисков ограничено высотой окна: если дисков больше, чем помещается, лишние недоступны, пока окно не увеличить.

### 1.5. Запуск и сканирование

- При запуске сразу сканируются все жёсткие диски, и показывается сводка. Пока идёт сканирование, по центру видны надпись «Scanning…» и индикатор прогресса.
- Любое действие пользователя во время сканирования прерывает его. Интерфейс не блокируется.
- **Аргумент командной строки** — путь к диску или папке. Программа сразу открывается приближенной к нему. На этом построена интеграция с меню Проводника: `.reg`-файлы добавляют пункт «Show Usage with Scanner» для `Directory` и `Drive` (`HKCR\…\shell\Scan_Content`).
- Список дисков строится только при запуске. Подключённую позже флешку программа не видит до перезапуска.

### 1.6. Подсчёт размеров

- Учитывается **занятое на диске место**, а не сумма размеров файлов. Каждый файл занимает минимум один кластер, размер округляется вверх до кластера.
- Для сжатых и разреженных файлов берётся реальный размер на диске (`GetCompressedFileSize`).
- Общий объём и свободное место диска не вычисляются, а запрашиваются у ОС (`GetDiskFreeSpaceEx`). Из-за этого сумма размеров папок может слегка (меньше 1%) расходиться с занятым местом диска.
- Содержимое корзины считается занятым местом.
- Точки повторной обработки (junction, symlink), ведущие в другие папки или на другие диски, не сканируются, чтобы не считать данные дважды.
- **Сетевые диски**: если большая часть содержимого пользователю не видна, показываются только видимые файлы, без деления на занятое и свободное место.
- Корзина распознаётся по имени папки в корне диска (`$RECYCLE.BIN`, `RECYCLER`, по префиксу `RECYCL`). Обычная папка с таким именем может быть принята за корзину.

### 1.7. Локализация

- Язык берётся из настроек Windows. Если в `Scanner.lang` есть перевод для этого языка, он используется, иначе интерфейс на английском.
- Формат `Scanner.lang`: блоки `имя_языка:`, затем `#<id>`, затем строки в фиксированном порядке (около 25 строк: «Scanning…», «Bytes», «Files», «Total», «Used on», «Free on», «Summary», «Recycle Bin», «Empty Recycle Bin», «Parent Folder», «Back», «Rescan Folder», «Version», «Zoom», «Rescan», «Open», «Recycle», «Remove», «Physical Device ID», «Show», «Hide» и т.д.). Кодировка — ANSI-кодовая страница языка.

### 1.8. Хранение настроек

`HKCU\SOFTWARE\Steffen Gerlach\Scanner`: размер окна, состав сводки, номера физических дисков.

### 1.9. Известные недостатки оригинала

- Только ANSI-API: проблемы с именами, содержащими некоторые символы (например `0xB4`), и с длинными путями.
- Окно фиксированного размера, масштабирование рывками.
- Новые диски не появляются без перезапуска.
- При запуске с аргументом не работает прогресс первого сканирования.
- Корзина распознаётся по имени.
- Номера физических дисков задаются вручную.
- Нельзя приблизиться к папке, слишком мелкой для отрисовки.
- Сетевые диски работают не на всех системах.

**Обязательно (MVP):**

- ✅ Полный Unicode и длинные пути (`\\?\`). Имена с непарными суррогатами помечаются как «искажённые», и действия с ними не выполняются.

- ✅ Поиск по имени и маске с подсветкой на диаграмме.
- ✅ Тёмная и светлая темы (по теме Windows).
- ✅ Удаление с подтверждением; безвозвратное удаление — только с явным подтверждением. Ссылки (junction, symlink) удаляются сами, без содержимого, на которое указывают.

### 2.4. Архитектура

```
┌──────────────────────┐  прогресс и частичное  ┌───────────────────┐
│  Сканер              │  дерево                │  Дерево (модель)  │
│  - обход папок       │ ─────────────────────▶ │  узлы, размеры,   │
│    (пул потоков)     │                        │  агрегация        │
│  - MFT               │                        └─────────┬─────────┘
│  - очередь на физ.   │                                  │ запросы: дети узла,
│    диск              │                                  │ раскладка, поиск, типы,
└──────────────────────┘                                  │ сравнение, дубликаты
                                                ┌─────────▼─────────┐
                                                │  UI               │
                                                │  sunburst/treemap,│
                                                │  панель, действия │
                                                └───────────────────┘
```

- **Сканер.** Разделы одного физического диска сканируются по очереди, разные диски — параллельно. Внутри диска папки читает пул потоков (до 8 на SSD, один на HDD); дерево собирает один поток. Отмена — через токен. Быстрый режим читает MFT тома блоками по 4 МиБ и строит дерево по ссылкам на родителя.
- **Модель.** Плоский массив узлов (родитель, первый ребёнок, следующий брат, размеры, число файлов и папок, флаги) и пул строк для имён. Размеры поднимаются к родителям по ходу сканирования; сложение насыщающее, так что повреждённые данные с диска не переполнят счётчики.
- **Раскладка.** Для текущего корня считается список видимых дуг (sunburst) или прямоугольников (treemap, алгоритм squarified). Мелкие объекты отбрасываются. Попадание курсора определяется по полярным координатам и бинарному поиску в кольце либо поиском самого глубокого прямоугольника.
- **UI** только рисует раскладку и вызывает команды. Тяжёлые запросы (поиск, типы файлов, сравнение, дубликаты, экспорт) выполняются вне потока интерфейса, результаты кэшируются по поколению дерева.

### 2.8. Известные ограничения

- **Сравнение снимков** — только для диска целиком и после полного сканирования. Объекты сопоставляются по точному имени: переименованная папка выглядит как удалённая плюс новая. Пока сравнение включено, снимок держится в памяти (примерно как ещё одно дерево).
- **Быстрый режим (MFT)** не показывает частичную диаграмму: дерево строится после чтения всей таблицы. Очень фрагментированная MFT (продолжение списка фрагментов в дополнительных записях) не читается — тогда используется обычный обход. Удаление в этом режиме выполняется с правами администратора.
- **Обычный обход** считает жёсткие ссылки по каждому имени (WinSxS, Edge), поэтому его итог больше, чем через MFT. Размер сжатых Windows файлов (CompactOS, WOF) запрашивается у системы, но на машине разработки это не проверено.
- **Действия** (открыть, удалить, пересканировать) недоступны для имён, которые Win32 не может адресовать обычным путём, и для «искажённых» имён.
- **Во время первого сканирования** диска удаление и пересканирование папок на нём отклоняются, пока сканирование не закончится.
- **Подпись exe.** Скрипт сборки подписывает exe, если указан сертификат (см. README). Без сертификата, выпущенного удостоверяющим центром, SmartScreen предупреждает о неизвестном издателе; самоподписанный сертификат этого не убирает.
- **Память после удаления:** узлы удалённых из программы файлов и папок остаются в памяти до полного пересканирования диска. Крейт `trash` может не справиться с путями длиннее 260 символов.
- **Здоровье дисков:** S.M.A.R.T. SATA-дисков доступен только с правами администратора (NVMe — без них). Диски за USB-переходниками и в RAID-массивах обычно данные не отдают (команды переходников SAT/JMicron/Realtek не реализованы). Названия атрибутов — на английском в обоих языках. Фонового слежения и предупреждений нет.
- **Перевод** охватывает интерфейс и сообщения бэкенда; несколько служебных ошибок («no such drive») остаются на английском в обоих языках.
